# Classbase 本番監視・障害対応ランブック

最終更新: 2026-10-03

## 1. 監視対象と判定基準

| 対象 | 確認方法 | 警告 | 重大障害 |
|---|---|---|---|
| Web稼働 | `GET /api/health` を5分間隔 | 1回失敗 | 2回連続失敗、または5分超継続 |
| Firebase接続 | `GET /api/health?deep=1` を認証付きで5分間隔 | 応答2秒超 | 503、10秒タイムアウト、2回連続失敗 |
| Vercel Functions | Observabilityの5xx率 | 5分間で1%以上 | 5分間で5%以上、または主要操作が失敗 |
| 応答速度 | 主要APIのp95 | 2秒超が15分 | 5秒超が10分 |
| Firebase読取 | Firebase Usage | 日次想定の120% | 日次想定の150%、または課金上限接近 |
| Zoom・LINE・メール | 検証アカウントへの日次疎通 | 1経路失敗 | 授業開始、参加、緊急連絡が不能 |
| 夜間録画同期 | Vercel Cronログ | 当日分失敗 | 2日連続失敗 |

監視サービスには公開Livenessと認証付きReadinessの両方を登録する。`OPS_HEALTH_SECRET` はVercel Productionと監視サービスだけに保存し、URL、文書、チャットへ記載しない。

## 2. 役割と初動時間

| 役割 | 責任 | 初動目標 |
|---|---|---|
| 一次対応者（運用マスター管理者） | 利用者影響の確認、障害宣言、画面告知 | 10分以内 |
| 技術対応者（アプリ保守担当） | Vercel/Firebaseログ確認、切り戻し判断 | 15分以内 |
| 業務責任者 | 授業・勤怠・給与の代替運用判断 | 20分以内 |
| 外部連携窓口 | Zoom、LINE、メール等のベンダー障害確認 | 30分以内 |

実名、電話、メール、時間外連絡先は組織の非公開連絡網へ登録し、このリポジトリには保存しない。一次・技術・業務責任者には必ず正副各1名を割り当てる。

## 3. 重大度

- P0: ログイン不能、全校舎で授業開始・参加不能、データ消失または漏えいの疑い。直ちに障害宣言し、更新操作を止める。
- P1: 複数校舎または主要機能が利用不能。30分以内の復旧を目標に切り戻しを判断する。
- P2: 一部利用者・一部機能の障害で代替手段がある。営業時間内に修正計画を提示する。
- P3: 表示崩れや軽微な操作性。通常改修として管理する。

## 4. 一次切り分け

1. 公開チェック `node scripts/check-production-health.mjs` を実行する。
2. 認証付きチェック `OPS_HEALTH_SECRET=... node scripts/check-production-health.mjs --deep` を実行する。
3. Vercelの最新Production DeploymentがReadyか、直近30分の5xxと例外を確認する。
4. Firebase Status、Firestore Usage、Authentication、Storageを確認する。
5. 影響する外部サービス（Zoom、LINE、Resend、Google、Monoxer）の公式ステータスを確認する。
6. 直前デプロイ時刻、障害開始時刻、対象ロール、校舎、操作、HTTP状態を記録する。個人情報やトークンは記録しない。

## 5. 切り戻し基準と手順

直前デプロイ後にP0/P1が発生し、15分以内に安全な修正を検証できない場合は切り戻す。ただし、旧版に既知のデータ破壊・認可不備がある場合は旧版へ戻さず、対象機能を停止して代替運用へ切り替える。

1. `npx vercel ls` で直前の正常なProduction Deploymentを確認する。
2. そのDeployment IDと、戻す理由・既知リスクを障害記録へ残す。
3. `npx vercel rollback <deployment-id>` を実行する。
4. 公開・認証付きヘルスチェック、ログイン、授業参加、打刻の順で確認する。
5. データ移行を伴う版はアプリだけ戻さず、復旧責任者がデータ互換性を確認する。

## 6. 代替運用

- 授業開始・参加不能: Zoomの承認済み緊急案内経路を使用し、参加者と時刻を別紙へ記録して復旧後に照合する。
- 打刻不能: 校舎別の障害時勤怠表へ開始・終了・校舎を記録し、復旧後に管理者の新規実績機能で登録する。
- 講師配置同期不能: Googleシートを正として手動インポートへ切り替え、復旧後に件数を突合する。
- LINE・メール不能: アプリ内お知らせと既定の緊急連絡網へ切り替え、同じ内容の多重送信を避ける。

## 7. 利用者連絡文面

初報:

> 現在、Classbaseの【対象機能】で障害を確認しており、【対象者・校舎】に影響しています。発生時刻は【時刻】です。復旧まで【代替手順】をご利用ください。次回案内は【時刻】までに行います。

復旧報:

> 【時刻】にClassbaseの【対象機能】が復旧しました。影響時間は【開始】から【終了】までです。障害中に行った【打刻・申請・授業参加】は【確認方法】でご確認ください。不一致がある場合は【問い合わせ先】へご連絡ください。

## 8. 復旧後

24時間以内に影響件数、欠損・重複、監査ログ、外部送信履歴を確認する。3営業日以内に原因、検知、復旧、再発防止、担当・期限を記録し、監視閾値と本ランブックを更新する。
