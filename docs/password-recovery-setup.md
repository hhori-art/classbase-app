# パスワード再設定機能の運用設定

## 実装済みの流れ

### 生徒・保護者（登録情報の照合）2026-11-01 から

1. ログイン画面の「パスワードを忘れた方」→「生徒・保護者」で、ログインID・氏名・校舎・学年・登録電話番号の下4桁・リンクを受け取るメールアドレスを入力します。
2. 保護者は、校舎・学年をつながっているお子さまのどれかで、電話番号を保護者本人の登録で照合します。生徒は、電話番号を本人か、相互に紐づいている保護者の登録で照合します。
3. すべて一致した場合だけ、入力したメールアドレスへ10分有効・1回限りの再設定リンクを送ります（事前のメール確認は不要）。
4. 乗っ取りに気づけるよう、本人と保護者（生徒の申し込みなら保護者、保護者の申し込みなら保護者本人とお子さまのアプリ）へ「再設定が申し込まれ、ab***@… に送った」ことを知らせます。アプリ内通知・端末通知に加え、LINE連携と確認済みメールがあればそちらにも送ります（通知の受け取り設定に関係なく送る）。
5. 同じアカウントへの申し込みは1時間3回・1日5回まで（電話の下4桁の総当たり対策）。申し込みは一致・不一致とも `password_recovery_events` に残し、一致した場合は宛先メールも記録します。

### 講師（確認済みメール）

1. 利用者がログイン後の「設定」で再設定用メールを登録します。
2. 届いた確認メールのボタンを30分以内に押すと、確認済みになります。
3. ログイン画面の「パスワードを忘れた方」→「講師」で、ログインID・氏名・確認済みメールを入力します。
4. 入力内容が登録情報と一致した場合だけ、10分有効・1回限りの再設定リンクを送ります。

### 共通

1. メールを利用できない場合は、同じ画面の「メールが使えない」から本人確認を申し込み、受付番号を発行します。
2. マスター管理者が登録電話への折り返しなどで本人確認した後、10分有効・1回限りの再設定リンクを発行します。発行したらすぐに本人へ伝えます。
3. パスワード変更後は既存セッションを無効化し、Firestoreに平文パスワードを残しません。
4. 新しいパスワードは `lib/password-policy.ts` のきまり（生徒・保護者・講師は8文字以上、よく使われるもの・IDに近いものは不可）で確かめます。
5. 変更したら、本人へ「パスワードが変更されました（日時・日本時間）。心当たりがなければ校舎かサポートセンター 078-321-4123 へ」と知らせます。アプリ内通知・端末通知と、確認済みの再設定用メール（`recovery_email` / `recovery_email_verified_at`）へ送ります。パスワードやリンクは書きません。知らせに失敗しても変更は取り消しません（`lib/server/password-reset-notice.ts`）。

### 再設定リンクのきまり（KDL診断 A.3.2・2026-11-12）

- 有効期限は、自分での申し込み・管理者の発行とも10分（`lib/password-reset-rules.ts` の `PASSWORD_RESET_TTL_MS`）。メールは GAS が1分ごとに送るため、受け取ってから使えるのは8分ほど。
- 1回だけ使える。使うときは `processing_at` → `used_at` をトランザクションで付け、二重に使わせない。
- 新しいリンクを出したとき（メールを送れたあと／管理者の発行時）と、パスワードを変更したときは、同じアカウントのまだ使えるほかのリンクに `revoked_at` を付けて使えなくする。
- 期限切れ・使用済み・取り消し済みのリンクを開くと、確認画面に理由を出し、「もう一度申し込む」（自分での再設定を止めている間はサポートセンターの電話）と、校舎から受け取ったリンクなら校舎へ再発行を頼むよう案内する。

一致しない場合も画面には同じ受付完了メッセージを表示します。アカウントやメールアドレスの存在を第三者に推測されないための仕様です。

## メール送信の初期設定（Google Apps Script・現在の方式）

DNS・管理コンソール・2段階認証なしで、onlinesupport@sozogakuen.co.jp の Gmail から送る。設定があれば Resend より優先する（パスワード再設定・申し込みのお知らせ・一斉通知のメール・講座運用レポート）。

会社の設定で GAS をウェブアプリとして外部公開できないため、アプリはメールを Firestore の `mail_outbox` に積むだけにし、GAS が1分ごとに `/api/internal/mail-outbox` へ取りに来て送る。そのため、届くまで最大1分ほどかかる。

1. onlinesupport@sozogakuen.co.jp でログインし、https://script.google.com/ で「新しいプロジェクト」を作る（名前：創造学園アプリ メール送信）。
2. 最初からある `コード.gs` の中身を消し、`docs/gas-mail-sender.gs` の中身を貼って保存する。
3. 関数の選択で `createSecret` を選んで「実行」。初回は許可を求められるので、onlinesupport@ を選んで許可する（「このアプリは Google で確認されていません」と出たら「詳細」→「〜に移動」）。実行ログに出た合言葉を控える。
4. Vercel の Production 環境変数に登録し、本番に反映する。

```env
GAS_MAIL_SECRET=<手順3の合言葉>
GAS_MAIL_FROM_NAME=創造学園アプリ
```

5. 反映後、関数の選択で `installTrigger` を選んで「実行」。メール送信と外部への接続の許可を求められたら許可する。ログに「1分ごとの送信を始めました」と出れば完了（左の時計のアイコン「トリガー」に pollOutbox が1件ある）。

- デプロイ（ウェブアプリ公開）はしない。
- 送信は 1 日 1,500 通まで。GAS が取りに来るたびに残り通数を `mail_delivery_status/gas` に記録し、300 通を切るとサーバーログに警告を出す。超えそうになったら、Resend（DNS 設定）など別の方法へ移る。
- 送れなかったメールは3回まで送り直し、24時間たったものは送らない。送ったメールは本文（再設定リンクなど）を消す。
- 合言葉を変えるときは `createSecret` を再実行し、Vercel の値も入れ替えて反映する。
- 送信を止めるときは、トリガーの画面で pollOutbox を削除する（アプリに積まれたメールは、Vercel の GAS_MAIL_SECRET を消すまで積まれ続ける）。

## メール送信の初期設定（Resend・DNS 設定が必要）

本番環境は Vercel Marketplace の Resend を使い、サーバーから直接送信します。配信APIがエラーを返した場合、画面に「送信しました」と表示しません。

1. Vercel Marketplace から Resend を接続し、`sozogakuen.co.jp` のDNS確認を完了します。
2. Vercel本番環境へ次の環境変数を登録します。

```text
PASSWORD_RECOVERY_BASE_URL=https://classbase-app.vercel.app
PASSWORD_RECOVERY_RATE_LIMIT_SECRET=<十分に長いランダム文字列>
RESEND_API_KEY=<Vercel Marketplaceが自動登録>
RESEND_FROM_EMAIL=創造学園アプリ <noreply@sozogakuen.co.jp>
```

`PASSWORD_RECOVERY_RATE_LIMIT_SECRET` は32バイト以上のランダム値を推奨します。設定後は本番を再デプロイします。

Firebase Trigger Email を使う環境だけ、`FIREBASE_MAIL_COLLECTION` を明示的に設定します。拡張機能がない状態では送信成功を返しません。

## 導入時の運用

- 全利用者へ、初回ログイン後に再設定用メールを登録するよう案内します。
- 生徒の再設定に保護者メールを使うには、生徒側の `parent_uid` / `parent_ids` と保護者側の `student_ids` が相互に一致している必要があります。
- メール未登録者は「メールが使えない」から受付後、マスター管理者が「全体アカウント管理 > パスワード再設定受付」で対応します。
- 電話番号下4桁の一致は確認材料の一つです。氏名・受付番号だけでリンクを発行せず、登録済み電話への折り返しなど別経路で本人確認してください。
- 発行した再設定リンクはパスワードそのものではありません。本人確認済みの利用者へ安全な連絡手段で伝え、第三者へ転送しないよう案内します。
- 管理者アカウントはこのセルフサービスの対象外です。マスター管理者による復旧と、多要素認証を利用してください。
- メール送信失敗は Resend のログとVercelの関数ログで確認します。
- 氏名変更時はユーザーマスターも更新します。
- 再設定メールを転送しないこと、共有端末では操作後にログアウトすることを案内します。
